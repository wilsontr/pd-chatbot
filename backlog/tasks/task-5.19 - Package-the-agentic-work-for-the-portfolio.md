## Architecture diagram (AC #1)

- `assets/architecture.svg` is generated by a small script rather than hand-drawn in a vector editor, so it can be regenerated when the module layout changes; it is plain SVG (no Mermaid), so it renders on GitHub, in an editor preview and on a portfolio page without a JS runtime.
- Four bands: interfaces (web/SSE, `pdbot`, MCP server, Slack dashed as planned), agent core (`chat.py`, `loop.py`, `guardrails.py`), the seven tools, and five backends. The Slack box is dashed and labelled planned because TASK-5.18 is still To Do — the diagram only claims what exists.
- The ASCII module sketch that used to sit under "Agent core" was removed: it duplicated the diagram and had drifted from it (it did not mention the patch tools at all).

## Self-correction demo (AC #2)

- The GIF is generated from a real recorded run, not written by hand. The recorder captures the tool-call/tool-result event stream (including `ToolResult.content`, which holds the Pd console text) and the builder draws the terminal from those events plus the waveform from the WAV the run produced.
- Recording took several attempts, and the attempts are themselves informative: self-starting oscillator patches run clean on the first try (no correction to show), while wavetable and UI-driven patches (`[table]` fill, `[tgl]` metronome) error *and* end silent — so they show a fix but no audio. The published trajectory is a reverb request: the first patch used `[rev1~]`, which vanilla Pd in the sandbox does not have (`error: ... couldn't create`), and the rewrite with a feedback delay line ran clean and rendered 220 Hz at peak 0.98.
- Recorded with a raised 120,000-token budget. At the default 40,000 the same question hit `budget_exceeded=tokens` at turn 4 while still mid-repair; the README caption states the sandbox backend, and this is noted in FAILURE_MODES.md under limits.
- Chosen run: `run_id=d92d3e3ffedd457eb544cb7cb7f3bd0c`, 6 turns / 8 tool calls, 4.0 s of audio.
- The final answer said plainly "The tail is not 3 seconds. I could not get a true 3-second reverb." — honest constraint reporting, quoted in FAILURE_MODES.md §6.

## Failure-mode write-up (AC #3)

`docs/FAILURE_MODES.md` covers five measured families plus one live example and a "what still gets through" section:

- `[line~]` list order and `[unpack]` misattribution (TASK-5.20), `outlet-order-unsupported` warning 2/3 → 0/5 (TASK-5.23)
- unconfirmed pd-patch inlet counts: 4/5 answers, judge caught 1/5, 0 of 180 after `agent/patch_counts.py` (TASK-5.24)
- the judge's own wrong inlet-order belief (TASK-5.22), with the 5/5/5 vs 2 table
- patch-spec measurement 73% → 92% (TASK-5.5 / PATCH_EVAL.md)
- limits: judge noise, narrow deterministic checks, libpd vs desktop Pd, budgets, scope gate not a security boundary

Every number comes from a task's recorded run or from the published reports; each cited code path and test file exists and is linked. The severity claims were checked against `evaluation/claims.py`: `line-list-order`, `inlet-order`, `invented-source` and `object-coverage` are gating, `outlet-order-unsupported` is a `WARNING`.
